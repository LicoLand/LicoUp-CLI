## 状态

2026-09-07 采纳为目标设计。实现由独立计划与对应证据交付。本文不改变当前支持、发布事实或已安装 MCP 工具目录。

## 背景

长期 Assistant 已经把面向用户的责任与临时 Graph 工具分开。尚需补充目标成立前及目标之间的连续性：理解用户表达、识别新旧事项、辨认实际委托、选择相关上下文，以及在原生 Session 替换后保留责任。

用户不应为了协作选择编码／目标／知识模式、刷新群聊、为避免上下文污染而新建对话，或手动往返于 Agent。范围包含研究、文档、协调与日常工作，而不只软件开发。编码分类和超长提示词都不足以成为组织原则。

## 决策

采纳[持续 Assistant 规范](../architecture/CONTINUOUS-ASSISTANT.zh-CN.md)，由它唯一拥有新增连续性语义。保留显式 Conversation Assistant 角色、规范 Event/Part 历史、Membership 准入、既有 PersistentTurn 与 Adaptive Flywheel 执行，以及原生适配器。

Agent 理解意图并提出事项、约定和承诺变更；确定性 Conversation 权威校验并提交。上下文按当前工作选择；原生 Session 保持为私有、可替换的执行绑定。目标跟进通过现有宿主安排重新检查。职责资格提供测得的准入依据，不复制能力／价格目录，也不引入加权智力分数。

本决策扩展 ADR 0004，不恢复已退役的交付调度器、固定 Designer／Worker／Reviewer 拓扑，或隐藏计划／历史权威。不静默更换指定 Membership。原生准确恢复失败仍如实记录；产品级重建接续是不同的新绑定操作。既有安全审批与真实作者信息保持不变。

## 替代方案

| 方案 | 不采用的原因 |
|:---|:---|
| 以编码模式分类作为目标入口 | 混淆专业能力与未完成责任，遗漏非编码工作 |
| 每回合强制先调用小模型 | 单次合格调用足以理解并回答时，额外增加延迟 |
| 永久增长的一个原生 Session | 把角色身份绑定到厂商状态，混合无关事项 |
| 新增不透明长期记忆库 | 混合事实、约定、知识和责任，缺少清楚属主 |
| 新增通用执行编排引擎 | 复制已有回合、Graph 与效果权威 |
| 所有 Agent 统一为纯文本接口 | 丢失原生工具、接续、审批及环境保真 |

## 理由

稳定产品抽象是协作责任，不是某个模型 Session。语义理解属于模型；权限、版本与效果执行属于确定性系统。分离后，更强、更便宜的模型可逐步取得职责资格，不必改变用户交互方式或重建执行基础。

上下文、知识与承诺语义分离，让检索、纠正、遗忘和跟进分别可测。基于实际能力使用原生执行，保留用户依赖的专业优势。

## 影响

实现增加有作用域的连续性聚合与来源关联、版本化理解／上下文端口、职责评估，以及宿主拥有的跟进机制。生成契约与私有运行时绑定通过协调迁移扩展，不在 Flutter 引入厂商分支。

先冻结共享契约，再并行实现独立职责。推广同时测量错误接管、漏接责任、任务成功、延迟、全链路费用和原生对照。旧对话迁移不编造目标或自动启动外部工作。可选知识服务继续独立发现，不成为必需基础设施。

## 实现证据

本次文档变更不声明运行证据。提升当前状态前，必须给出契约验证、状态机和恢复测试、持续多领域场景、模型评估、原生对照，以及相应平台与适配器证据。本地计划和原始验证输出继续遵循忽略路径策略。
