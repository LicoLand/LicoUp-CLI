# ADR 0009: 全局文档单一事实源（SSOT）与细分领域索引规范

状态：已实现（Implemented）

## 背景

随着 LicoUp 代码库与文档体系的演进，系统中的各类规范与实现细节（包括但不限于：四大架构分层、统一 Conversation 领域模型、端点安全与加密规范、下属智能体协议、Flywheel 策略、平台原生系统适配细节、模型定价与能力清单等）曾出现被反复复制并堆叠到上层概述文档或多个并列文档中的现象。

这种文档结构带来了严重的系统性问题：
1. **多头维护与事实漂移**：当某个子系统或协议的规则、状态机演进时，散落在各处的副本往往无法同步更新，导致文档之间出现相互矛盾。
2. **概述文档臃肿与层级混乱**：顶层概述文档（如架构总览、协议总览、功能总览）被大量具体的底层细节塞满，模糊了系统全局抽象与局部子系统之间的边界。
3. **单一事实源（SSOT）缺失**：开发者和自动化审查工具无法快速定位哪一份文档才是某个功能或机制的终极裁决者。

## 决策

本项目的所有技术与产品文档（涵盖架构、协议、功能、平台、运维及贡献规范）必须全面遵守以下编写与组织规则：

1. **全局单一事实源原则（Single Source of Truth, SSOT）**：
   - 全仓库中，任何一个架构模型、领域概念、线协议格式、生命周期状态机、安全加密规则或平台能力，**必须且只能有一份唯一的权威拥有文档（Authoritative Owner Document）**。
   - 任何其他文档如果需要使用或提及该概念，**必须通过链接或索引表格指向该权威文档，严禁大段复制、改写或分叉同一事实**。
2. **顶层与概述文档的“模块化与瘦身”规则**：
   - 顶层概述文档（如 `docs/architecture/README.md`、`docs/protocols/README.md`、`docs/functionality/README.md` 等）必须保持精炼与高层抽象，只描述跨领域的顶层分层、流向图与通用规则。
   - 所有细分领域的具体设计必须下沉到专属文档中，并在顶层文档中通过 **结构化索引表格（Index Tables）** 建立清晰的导航与权责映射。
3. **结构化索引表与引用表标准**：
   - **文档顶部关联引用**：每份文档顶部的跨文档引用（规范版本、本地化版本、产品定义、状态文档等）统一采用 Markdown 表格形式，声明目标路径与权威职责。
   - **细分领域架构/协议索引表**：概述性文档必须提供标准化表格，列出细分领域名称、所属层级/分类、权威规范文档链接及核心职责概述。
4. **产品理念与技术事实分离**：
   - 产品愿景、设计哲学（多元、互联、开放、融合）与顶层用户承诺统一归属于 `PRODUCT.md` / `PRODUCT.zh-CN.md`。
   - 技术架构与协议文档专注于技术事实、系统边界、契约与代码映射，不混入产品宣传文案。
5. **双语事实严格同步**：
   - 英文文档为技术事实的权威规范（Normative），简体中文文档为本地化投影并链接回英文版本。两者所包含的技术事实必须严格保持同步。

## 各文档分类的 SSOT 归属矩阵

| 文档分类 | 目录位置 | 权威拥有范围 | 编写规则要求 |
|:---|:---|:---|:---|
| **产品目标与理念** | `PRODUCT.md` | 产品愿景、设计哲学、顶层安全与隐私承诺、命令身份原则 | 作为顶层纲领，不展开底层代码实现细节 |
| **顶层系统架构** | `docs/architecture/README.md` | 四层客户端架构体系（外观层、桥接层、核心层、原生层）及 Native 系统适配边界 | 不内嵌具体子系统细节，通过索引表导航至专属文档 |
| **细分领域架构** | `docs/architecture/*.md` | Conversation 领域模型、安全与数据边界、桥接协议交互边界等 | 拥有该领域的唯一模型图、状态表与实体定义 |
| **功能特性规范** | `docs/functionality/*.md` | Adaptive Flywheel 策略、桌面客户端能力边界、用户指南、设计系统 | 专注于该功能的独立机制与生命周期 |
| **线协议与接口** | `docs/protocols/*.md` | Subagent MCP、Conversation MCP、Lico Agent、LLM Gateway、Station Adapter | 严格定义线协议字段、信封格式、RPC 交互与 Codec |
| **平台适配与合规** | `docs/platforms/*.md` | macOS 站外分发合规清单、各 OS 平台专用要求 | 记录非可移植的操作系统特定规范与发布合规事实 |
| **当前状态与兼容性** | `docs/STATUS.md`, `COMPATIBILITY.md` | 当前真实实现状态、平台/13 智能体支持矩阵（生成投影） | 唯一事实源，不得在其他文档中编造未实现能力 |

## 影响与收益

- **消灭文档漂移**：任何机制修改只需在对应的专属权威文档中更新一次。
- **层级分明，易于检索**：从顶层概述到细分领域的跳转路径完全由索引表格驱动，结构高度透明。
- **便于自动化审计**：架构门禁与 CI 脚本可基于 SSOT 权威文档直接进行边界校验，无需解析混乱的多处副本。
