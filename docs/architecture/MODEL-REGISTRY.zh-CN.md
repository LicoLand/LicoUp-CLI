# 全局模型注册表

简体中文 · [English](MODEL-REGISTRY.md) · [架构](README.zh-CN.md)

本文拥有 Rust 客户端核心的标准模型身份。Agent、模型开发者、服务供应商、
可选模型 ID 与模型本身是不同身份。Flutter 仅呈现核心给出的模型 ID 和
显示名称，不维护第二套目录，也不自行归一化各 Agent 的名称。

## 目录与刷新

进程共享不可变的注册表快照。公开模型事实与供应商到模型的引用来自开源
[Models.dev 源目录](https://github.com/anomalyco/models.dev)。刷新读取官方
源码归档，保留明确的 `base_model` 引用。本地 Agent 目录保留原生选择器
ID、名称和准入选项；注册表为其投影附加标准身份。显示名称匹配不代表获准
调用，也不会改写原生派发选择器。

用户主动刷新时，先更新公开目录，再刷新本地用量。后台读取用量不会为每份
报告或记录下载目录。没有目录时，桌面先展示本地统计，再尝试一次后台目录
刷新；失败不会自动循环重试，用户可主动重试。读取使用共享索引快照；刷新
成功后原子发布新快照。
其它本地进程在请求边界观察更新。下载或解析失败时保留最后可用目录，并
向调用方报告刷新失败。

显式选择的状态目录拥有自己的模型缓存。报告仅捕获该目录的快照，不继承
或替换默认进程注册表；正常桌面路径继续共享全局单例。

刷新只下载公开事实，不向目录服务发送用量、模型选择、凭据、对话或原生
历史。注册表命令均为本地 CLI 能力，不扩大远程 Subagents MCP 的能力范围。

### 已安装 DeepSeek Harness 的模型目录

选择目标后的发现流程沿用已有 Agent 查询授权，通过已安装官方
`dsh-llm-deepseek` 适配器的 `listModels` 与 `resolveModel` 读取模型元数据。
该查询不启动 profile、不应用插件、不读取凭据或用户设置，也不发送模型请求。
建议性模型目录和支持的思考选项由安装包提供；LicoUp 保留原生模型 ID 与服务
供应商路由。目录成员不证明账户权限或历史请求的实际型号，也不创造默认模型。

对话使用官方 `dsh --profile sdk` 入口启动。模型、供应商、工作目录和可选的
思考强度经 `initialize` 传入；实际设置保留选中强度，复用 SDK 会话时不得静默
更改。模型发现成功不代表对话就绪验证通过。运行时准入、Assistant 指导语投递
与消息发布由 [ADR 0005](../adrs/0005-assistant-auto-adaptation-and-deepseek-harness.md)
维护。上述模型契约分别由官方
[适配器元数据](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/llm/llm-deepseek/README.md)
和 [SDK profile](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/bundle/sdk-app/README.md)
定义。

## 标准模型身份

注册表分别索引标准 ID、名称与供应商选择器。供应商后来改变 API 别名的指向，
不改变明确的标准身份。明确供应商元数据用于消除原生选择器的歧义；仅有 Agent
名称不能确定它调用的服务供应商。
匹配必须唯一：格式差异、Agent 包装、上下文窗口后缀、请求思考强度和速度
选项，不应为同一模型创造第二个身份。版本、实质不同的模型变体和模态差异
必须保留。

官方确认属于执行模式的选项共享注册表身份，即使公开目录将它们分行列出或尚未
收录。[Composer 2.5 及其 Fast 模式](https://cursor.com/docs/models/cursor-composer-2-5)
在各 Agent、可选模型目录元数据和用量报告中均解析为 `cursor/composer-2.5`。
保留报告中先前独立的 Fast 身份也会合并。原生选择器与原始记录保持不变；明确的
Fast 后缀作为执行速度保留，实际请求元数据优先。裸模型 ID 不能证明是否启用
Fast。该已确认的等价关系不会移除其他模型身份中的 Fast。

正式供应商 ID 使用独立命名空间。显示名称别名不能覆盖正式 ID，也不能在本家
查不到时转去匹配另一家的选择器。历史统计只采纳标准身份与明确版本别名；今天
浮动接口的指向不能证明旧请求实际用了哪个版本。保留报告中已确认的标准归属
保持稳定，即使该模型从当前目录移除；显示文字仍可更新。

结构化选择器按结构解析。例如，`id: k3`、`providerID: kimi-for-coding`
与 `variant: max` 给出三个独立事实，其序列化 JSON 绝不是模型名称。明确
指向同一基础模型的上下文变体共享身份。只有供应商名称或自动选择器，不能
证明实际回复的模型。歧义和未知名称不得被猜测归入某个模型。

上游更新后目录能够扩展，无需逐个新增前端模型适配。公开目录不代表已收录
全部私有、更名或刚发布的模型。未解析的原始身份继续保留，使后续目录能够
重新归属，同时不丢失 Token 计数。

完整 JSON 选择器及其 JSON 字符串封装必须先解码，再查找模型身份。损坏的容器
残片、默认或自动路由标签不能成为模型名，也不能被过期的标准身份标记保留。
原始记录和全部计数继续保留在未归属用量中。不得根据显示残片或当前目录的
匹配结果，补造已经丢失的命名空间或请求字段。

## 显示名称

同一注册表独立提供面向用户的名称，不把显示排版当作身份匹配。目录产品名称
保留品牌拼写与版本；单词间使用空格，例如 `DeepSeek V4 Flash`、`DeepSeek V4 Pro`
和 `Claude Fable 5.1`，GPT 版本前缀则保留 `GPT-6 Astra` 中的连字符。供应商
命名空间、API 分隔符与请求控制后缀不作为显示名称。未收录名称也按统一的可读
分词格式展示，包括 `GPT Reserve` 与 `Grok Bot`，但不因此猜测标准模型身份。

只读工作流检查也为已保存但未出现在当前可选目录中的模型提供显示名称。
Flutter 将名称传到已保存路由的胶囊，不改变绑定、授权摘要或实际调用的选择器。
渲染标签不会重新扫描模型目录。

官方产品参考包括 [Claude Fable](https://www.anthropic.com/claude/fable) 与
[DeepSeek V4.1 公告](https://www.deepseek.com/en/news/deepseek-v4-1-flash/)。服务别名
可能独立于模型名称发生变化。刷新别名
不得改写历史记录中明确的旧版本身份。

## 用量与实际思考强度

缓存分别保留原始模型选择器和实际请求控制参数，不以标准报告身份覆盖原始
事实。新报告采用快照中的历史身份规则；保留报告固定已确认归属，并允许补全
之前未知的明确模型身份。标准模型总量合并全部来源 Agent；
来源总量及有证据的强度、速度明细保留在该身份下。

实际强度来自已记录的请求、turn、消息或明确选择器元数据。提取覆盖运行时
Agent 清单，在增量解析和缓存重载中保留请求上下文。支持的思考选项、能力
评分和用户当前配置，都不能证明历史请求的实际强度。解析器改变时迁移已有
计数事实并刷新可重建的元数据；不清空已封存历史，也不补造旧记录缺失的请求选项。

受支持 Agent 清单决定扫描覆盖和已保存报告的显示范围。保留 Kimi Code，
移除 Kimi Desktop 适配；移除适配不删除用户历史、配置或已保存的计数记录。
来源未保留 Token 元数据时报告不可用；把 Agent 纳入扫描不能创造历史
Token。任意命名的模型预设也不是
思考强度，除非同一记录提供实际选项，或选择器本身具有已知的强度含义。

Lico Agent 为每次模型响应记录数值用量，包括发起工具调用的响应。统计
记录与对话文字分开保存，恢复对话时不加入模型输入。后续调用失败也保留
已完成调用的计数；响应里的实际模型优先于同次调用明确请求的模型。

缺失强度保持缺失，不产生 `Unspecified`、`default` 或 `unknown` 行。
部分请求缺失强度不减少模型或来源总量；已知强度行仅描述提供了该事实的
请求。归一化保留输入、缓存输入、输出、总 Token 和请求计数。

[桌面用量场景](../functionality/CLIENT-DESKTOP.md#scenario-s-05--desktop-token-usage)
拥有来源与去重边界；[设计系统](../functionality/DESIGN-SYSTEM.md)拥有配色
与悬浮卡片，两者均不形成第二个模型身份权威。
