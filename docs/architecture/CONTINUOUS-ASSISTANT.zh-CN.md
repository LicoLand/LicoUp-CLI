## 1. 目的

用户持续与一个可见的 Assistant 合作，不必管理编码模式、模型会话、上下文重置或独立的记忆界面。Assistant 可以回答、讨论、协调专业工作、等待，并回到尚未完成的承诺。编码只是一类专业能力，不是 Goal 的定义。

连续性由产品负责，推理由可替换的 Agent 提供。持续 Conversation 不要求无限增长的提示词或永不结束的原生 Session。自动组织减少用户管理模式的劳动，但不隐藏真实作者、审批、费用和外部目标。

## 2. 词汇与权威

以下词汇属于本目标设计；仓库既有词汇仍以 [CONTEXT.md](../../CONTEXT.md) 为准。

| 对象 | 含义 | 唯一属主 |
|:---|:---|:---|
| Assistant 角色 | 附着于 Conversation 显式 Assistant 指定关系的持续责任 | Canonical Conversation |
| 指定代际 | 显式指定的 Membership 发生变化时形成的版本边界 | Canonical Conversation |
| Matter（事项） | 将交流材料关联到同一主题或活动的可修订组织结构 | Conversation 连续性状态 |
| Commitment / Goal（承诺／目标） | 从用户已表达意图接纳的、有界且尚未交付的结果；Goal 是其持久跟踪记录 | Conversation 连续性状态 |
| Agreement（约定） | 有来源、作用域、生效与替代版本的决定或约束 | Conversation 连续性状态 |
| 理解提案 | 宿主从用户和 Agent 实际说了什么里读出的理解 | 认知能力得出，Conversation 校验并提交 |
| 上下文组装 | 为一次调用选择的、获准使用的原文、约定与工作引用 | 上下文组合边界 |
| 工作上下文 | Matter、Membership 与原生执行 Session 之间的私有版本化绑定 | 既有运行时绑定属主 |
| 跟进事项 | 重新检查未解决 Goal 的持久原因 | Conversation 宿主，复用既有派发 |
| 职责资格证据 | 对某个候选承担指定职责的版本化评估 | Agent 能力评估属主 |
| 任务会话关系 | 将持久 Goal 绑定到一个父 Conversation、一个规范子 Conversation 和一张父卡片锚点 | Conversation 连续性状态 |
| 父卡片锚点 | 任务卡片占据的原始父 Event/Part 序号 | Conversation 连续性状态 |
| 父上下文授权 | 面向指定子会话接收方的、有作用域的父 SourceRef 授权 | Conversation 连续性状态 |
| 目标完成转换 | 已验收的 Goal 生命周期变化及既有通知身份 | Conversation 连续性状态 |

角色不是隐藏的 Agent Principal。被委派者仍是显式准入的 Membership。更换模型、原生 Session 或专家，不会静默更改指定 Assistant。用户明确替换 Assistant 时推进指定代际，使旧决策认领失效，同时保留输出来源。未完成 Goal 继续归属该角色；在途操作保留原 Membership、代际和效果身份用于对账。

规范 Event 只保存一次。事项关联可以是多对多，指向消息片段或 Part；一条复合消息可以更新多个事项。重新分类追加修订，不重写用户原文。Matter 不是第二套 Conversation、权限捷径或隐藏历史。普通聊天留在父 Conversation，不强制创建子会话。获准的持久长程工作自动获得该父会话下的一个真实规范子 Conversation，并带有已准入 Membership 与真实 Event/Part/PersistentTurn 历史。父会话只在原 Event 序号保留一张任务卡片。首个交付属于拥有该 Event 的 Conversation。父子关系不扩大数据、参与者或模型权限。任务需要的父上下文只能通过已准入、指明接收方和准确 SourceRef 的 ParentContextGrant 进入子会话。

## 3. 职责分离

| 职责 | 拥有什么 | 不拥有什么 |
|:---|:---|:---|
| 语义理解 | 意图、候选事项、承诺提案与能力需求 | 权限、预算、执行终结 |
| 上下文组合 | 相关且获准的输入、来源、上下文转换决策 | 规范历史或厂商内部压缩 |
| 目标跟进 | 未满足条件、证据引用、等待、后续注意事项与闭环 | 第二套 Graph 引擎或工具执行器 |
| 职责资格 | 指定职责上的测量结果与候选资格 | 复制模型、价格、Skill 或运行时目录 |
| 既有执行宿主 | PersistentTurn、Graph 准入与效果对账 | 仅根据运行结束认定用户目标达成 |
| Flutter | 交互、可检查投影与控制 | 话题分类器、生命周期合成或后台调度 |

实现继续沿用四层客户端架构。连续性聚合与版本进入现有 SQLite/WAL Conversation 存储；Rust 服务经强类型端口协作；生成桥接契约向 Flutter 投影事实；原生适配器保留各自协议实现。不以拆分微服务、中心化云后端或新增通用记忆数据库作为前提。

## 4. 理解意图与进入目标

语义理解由 Agent 完成。词法规则和索引可以提供候选或执行限制，但不能决定用户是否委托工作。理解应区分四个独立维度：

- 主题：新事项、既有事项、恢复旧事项、复合关联或尚不确定。
- 言语行为：询问、探索、委托、纠正、审批、暂停、取消、引用或假设讨论。
- 责任：没有待交付结果、有界即时工作、持久跟进，或既有授权周期策略的一次实例。
- 能力：下一步需要的技能、工具、环境和专业知识。

明确请求可以直接形成 Matter 和 Goal，无需切换模式或填写表单。探索可以保持未委托状态，讨论也可以在后续转为承诺。描述开发可能性不等于要求实施；非编码工作同样可能持续数天。Assistant 可以提出初始验收定义，但必须解决影响结果的重要歧义，不得静默降低用户定义的验收标准。

理解提案记录宿主从一次交流里读出了什么：用了哪些来源 Event 和 Part、当时的 Conversation 版本与指定代际、候选事项、相关约定版本、建议的变更、能力需求，以及不确定的原因。原始输入保持不变。模型自己报的置信度不是权限，也不是完成信号。未知字段、过期版本和没有授权的引用一律拒绝。提案由宿主从用户和 Agent 实际说了什么里得出；绝不要求 Agent 的回复承载它，也绝不要求它符合什么形状。

提案通过 Conversation 的 compare-and-set 校验提交。读取与理解不产生业务效果；语义提案不是可执行命令。修正事项关联不会删除已有执行、转移权限，或把在途效果转给另一个目标。

一次 Agent 调用可以同时完成理解和回答。评估证明值得增加一跳时，也可以先使用经济型理解者；不规定每条消息都必须经过分类器。缺少上下文时先有界检索；仍有歧义时升级推理或自然澄清。便宜理解者不得成为丢失原始用户意图的信息瓶颈。

## 5. 信息生命周期，而非记忆孤岛

| 信息类别 | 持久化与权威 | 上下文用途 |
|:---|:---|:---|
| 会话事实 | 原始 Event/Part 与来源 | 按需读取准确依据 |
| 约定 | 有作用域、生效期与版本的决定 | 纳入当前相关约束 |
| 领域知识 | 已准入的知识或来源属主 | 读取来源版本与新鲜性 |
| 目标状态 | 条件、等待、证据和未履行责任 | 恢复当前工作义务 |
| 工作笔记 | 可能有误、有来源、可替换的辅助材料 | 仅在有用时纳入 |
| 原生执行状态 | 运行时私有 Session 与工具环境 | 经受支持的原生连续机制保留 |

时间过去不会自动把陈述变成知识。旧的猜测仍是猜测；刚确认的决定可以立即生效。Agent 推断的偏好与用户直接表达必须可区分。摘要不能覆盖约定来源，也不能制造完成证据。矛盾、替代和作用域缩小都应明确记录。

关键约定和目标变更在后续相关工作之前提交。可选整理允许在有界的本地维护任务中完成，但不能延迟用户纠正、阻塞输入框或隐藏付费调用。原始记录遵守用户保留策略，不要求无条件永久保存。

删除或撤销使相关索引、摘要、组装结果和可复用工作上下文失效。权限或约定变化后，派发前重新验证组装结果。已经向服务商披露的信息不能被系统召回，产品须准确说明实际边界。本地派生存储不能从旧摘要或旧备份代际中静默复活已删除信息。

可选 Requirement Cognition 与 Knowledge Domain 服务继续独立拥有各自数据。LicoUp 经已准入的发现边界读取其声明的版本化能力，不镜像另一个仓库的端点清单或 Schema。只读查询不会创建需求或知识。服务不可用时返回具名 unknown 或 source-unavailable，不猜造知识或自动远端建档。本地连续协作不依赖这些服务运行。

## 6. 上下文组合与注意力

用户可见时间线、当前关注点、未完成工作与原生 Session 是不同维度。切换话题改变注意力，不改变无关 Goal 的状态。迟到结果关联回原事项，可以呈现通知，而不必将旧事项全部灌入当前模型上下文。

组装从有界的起始材料开始：当前准确输入、少量近期交流、获准的候选事项、当前约定和待回答问题。Agent 通过检索逐步完善选择。候选检索结合准确引用、实体、词法与近期性；语义检索是可选能力，不是规范存储。检索前与披露前均执行访问控制。

每份组装结果记录来源版本清单、相关约定版本、可见作用域、目标接收方、Token 估计和选择理由。实际内容保持私有并遵守保留策略；公共回执只含准许的非敏感标识和原因码。取回的文档和旧消息是数据，不是高优先级指令。来源内容不能通过提示注入扩大能力、修改策略或触发外部效果。

| 决策 | 前提 | 行为 |
|:---|:---|:---|
| 继续 | 同一相关工作且绑定准确有效 | 原生续接，增量提供上下文 |
| 压缩 | 同一工作、上下文过量、原生能力已验证 | 原生压缩，保留有来源检查点 |
| 分叉 | 明确复用获准的推演或工作分支 | 仅在继承语义已知时原生 fork |
| 新上下文 | 无关事项或需要隔离 | 创建干净且获准的工作上下文 |
| 重建接续 | 旧绑定不可用、过期或不适合 | 从获准、有来源状态创建新绑定 |

提示缓存失效只是成本或延迟观察，不是语义遗忘，不能单独触发压缩、目标关闭或归档。长时间后返回旧事项，即使原 Session 可恢复，也要刷新相关事实和假设。继承无关历史的 fork 不是隔离。原生记忆、工作区规则和环境工具同样纳入隔离检查，仅过滤发出提示词并不足够。

准确恢复失败仍是恢复失败。重建接续是单独记录的新绑定操作，不能藏在适配器 resume 方法里作为静默 fallback。由此保留已有准确 Session 完整性。

## 7. 原生执行保真

WorkContext 为私有绑定，按 Conversation、Membership、Matter 和绑定代际定界。回合及其效果固定准确代际。已有未分配事项的原生历史迁移为 legacy-context 记录，不编造 Matter。理解者可从获准历史提出关联，但迁移不会自动重放回合或创建目标。

适配器协商区分 supported、unsupported、unverified 和暂时不可用。恢复、分叉、压缩、steer、审批、工具、多模态及工作区隔离分别建模，不根据 Agent 名称或协议家族推断普遍支持。

LicoUp 委派有界结果、约束和证据引用，而非微操原生执行循环。原生工具、配置、Skill、环境、模型与推理设置继续由现有属主提供。产品连续性可以统一，保真等级依赖实际能力；不能把所有 Agent 降成文本输入输出。

LicoUp 只按 Agent 原本产出的样子显示它的回复。连续性从回复本身得出它是什么意思。绝不要求回复符合格式，也绝不把自然语言判成无效、空回复或弃权。如果一条回复必须先符合某种形状才能被理解，那就是缺陷。

同一个原生 Session 同时只有一个修改者。独立专业工作进行时，前台对话仍需保持响应。并行上下文必须有运行时能力证据及资源准入。不支持时在准确边界排队，或使用另一个明确准入的 Membership；不能启动冲突修改者，也不能静默替换指定 Assistant。

原生运行时拥有内部压缩，LicoUp 拥有可移植约定、目标、来源和交接检查点。双方在明确边界交换增量，不独立重写同一执行历史。原生标识、凭据、Session 路径不进入公共桥接回执。即使 Assistant 汇总结果，规范 Event 仍保留委派者真实作者身份。

## 8. 目标跟进与闭环

Goal 记录来源意图、版本化预期结果、验收条件、范围、负责角色、资源边界、关联执行、证据、下一关注安排和结束性质。Goal 与回合、Graph run 不同。

本轮是否继续、Assistant 对结果的判断、约定验收及外部效果结算是不同事实。Assistant
可以结束回合，同时保留验收未验证或效果未结算；不能伪造成功，也不能据此强迫追加模型
调用。普通聊天无须持久 Goal，这些区分不要求 Agent 自然回复增加字段或完成宣言。
以下 Goal 生命周期仅适用于明确跟踪的工作。

生命周期为 active、waiting、verifying、achieved、cancelled、superseded。后三者是吸收终态。重新开展工作创建关联的新目标，不擦除过去闭环。暂停是独立调度控制。取消请求立即禁止新增工作，最终取消须处理相关在途操作的对账。阻塞是具名事实，不是假成功。

每个未终结且未暂停 Goal 都有下一关注记录：正在执行的关联工作、可派发的下一步，或者带恢复触发与复查策略的具名等待。不允许仅显示“进行中”却没有负责的下一步、等待或检查。暂停目标保留原因与恢复途径。

运行结束、callback 和新的获准证据可以唤醒已登记的外部等待；用户回答可以请求继续工作。定时复查须有既有授权触发，重复事件合并。到期、未验收或未完成 Goal 本身不授权模型调用，也不制造成功、失败、审批或外部事件。已结束回合可以等待证据或用户验收。

Assistant 决定是否继续。Goal 跟踪记录尚欠结果及未验证项，不施加外层模型循环。PersistentTurn 或 Adaptive Flywheel 经原有派发、权限、资源与效果门执行已接纳动作；原生终态不能替代约定验收。

闭环要求所有必需条件具有当前有效证据、符合约定验收方式，且不存在可能推翻结果的未决操作。可机械验证条件使用确定性判据；主观条件使用约定评估者或用户验收。执行者自报、Graph 终止、送达回执、Worker 退出、审阅回合或 PersistentTurn 结算都不能单独关闭目标或发出 GoalCompletionTransition。已验收闭环只就地更新原父卡片，并通过稳定 `notificationId` 发出一条既有系统通知。不抢焦点、不追加替代完成消息是该转换的不变量，不是可配置导线字段。重试、复审和重启沿用同一 Goal、子 Conversation 与卡片身份。卡片保持原 Event/Part 与序号，`partId` 属于该身份。

进展依据是新增有效证据、减少不确定性、满足条件或解除阻塞。连续工作没有上述变化时，按有界策略调整路线、升级或暂停。重试、费用和工作量计入资源边界，不依赖无限“继续”提示词。持续维护目标形成有界评估区间或实例，而不是永久运行的回合。

## 9. 持久化、并发与效果

连续性状态、已接纳来源事件游标和跟进 outbox 在 Conversation 存储内原子提交。Outbox 向现有宿主可靠交接，不成为第二执行权威。消费按至少一次处理，以稳定的逻辑唤醒和效果身份去重。

认领携带聚合版本、指定代际和宿主代际。并发理解提案经 compare-and-set 提交，过期提案重新计算或被拒绝，不能覆盖用户纠正。重试沿用逻辑效果身份；新 turn ID 不构成重复已有效果的理由。

崩溃后，既有冷恢复保留回合中断／失败事实。目标恢复先对账再派发。明确未执行、明确已执行、执行情况未知三者独立；未知外部结果在任何重放前查询或复核。目标服务不支持相应契约时，不声称全局 exactly-once。

关闭界面是观察者断开；暂停抑制后续推进；取消请求终止并对账；删除来源执行保留策略。这些操作不可互相替代。

初始宿主为用户控制的本地 Rust 运行时。休眠和关机暂停实际执行；恢复后合并错过的复查，核对新鲜性再行动。系统定时器不等于保证后台运行。未来常在线宿主需要明确端点准入、单活拥有代际、安全转移与撤销；不会使 Station 可信，也不改变 Lico Arc 的线路职责。

## 10. 职责资格与经济型路由

按职责评估，而不是给模型一个通用智力分数。候选身份绑定模型与推理设置、提示或 Skill 摘要、上下文策略、工具契约、适配器／运行时版本、数据集版本及策略修订。这些是评估来源，不是第二套目录。模型价格、工具、Skill 与 readiness 继续从现有属主读取。未知或过期资格不能被提升为已验证能力。

评估属主保存观测及其作用域。路由使用硬准入和现有候选排序，可用比较证据改善未来默认策略。普通工作不以资格测评为前提，简单任务不强制多 Agent、Reviewer 或额外 Judge。不另建路由目录替代 ADR 0004。

必须评估事项关联、委托与假设区分、跟进需要、当前约定、证据新鲜性、上下文选择、专业能力选择、纠正、取消与适当保留判断。同时测试漏接责任和错误接管。训练、调优及留出数据按完整 Conversation 或 Matter 家族划分，不随机拆分相邻回合。覆盖多领域、多语言对话。

覆盖率和选择性错误率一起报告，避免“全部拒绝判断”通过。使用留出结果与置信区间校准，而非模型自信度。与固定强基线比较每个验收结果的全链路费用、用户纠正成本、路由延迟和原生能力损失。产品契约不固定模型品牌或价格。

推广依次经过离线合成评估、获准影子观察、有界低风险启用，再扩大职责覆盖。影子处理与真实工作遵循相同披露规则，不能静默把私人交流发给新服务商或付费评估者。退化或候选身份变化撤销资格；保留用户明确选择，不伪装尚未支持的自动化。

比较包含失败、取消、在途、返工和迟到费用，先控制任务难度构成变化，再声称改善。
证据不足沿用当前默认，不购买额外实验。自动采用可撤销且仅影响已获准未来选择，
不能修改在途绑定、验收条件、权限或预算。

## 11. 权限与体验

自动理解可以在当前委托内组织本地状态，不授予外部访问。每次模型调用、上下文披露、专家变更与工具效果都走适用的准入和审批路径。新接收方、扩大的内容或实质范围变更，不能仅凭目标、定时器、安装或旧审批获得授权。

没有强制的目标／编码／知识模式选择器，也没有需求提交表单。用户继续普通聊天。当 Assistant 接纳持久长程工作时，产品在父会话二级列表创建一个规范子 Conversation，并在创建该任务的 Event 序号留下一张主时间线卡片。协调者、Worker、Reviewer 以真实作者身份在子会话交流。进展与已验收完成只更新同一张卡片，不得重新插入、置顶或移动后续消息。A、B 两个子任务保持不同序号；后完成者不能改变先创建卡片的顺序。用户经自然对话或无障碍控件纠正关联、调整约束、暂停或取消。检查详情保留真实参与者、来源和费用。不能以无缝为由跳过必要审批。

Flutter 渲染 Rust 投影，不从文字、静默、动画或观察者连接推断生命周期。分类和知识整理不在 Flutter 运行。按能力保持长工作期间的前台响应，宿主不可用时不声称仍在工作。

## 12. 验证与采纳

验收覆盖持续、交错的协作，而非孤立提示词。必需场景包括非编码委托、编码作为一类能力、探索不接管、复合事项、返回旧话题、作用域纠正、迟到证据、主观验收、取消、崩溃恢复、未知效果、角色替换、原生记忆隔离、权限变化、缓存失效、知识不可用、数据删除、模型退化、A/B 子会话乱序完成、真实 Worker/Reviewer 作者与隔离、稳定重开／重试／重启，以及不抢焦点的单条既有系统完成通知。

确定性测试证明状态、权限、隔离和幂等不变量；模型评估测量理解与成本路由；原生对照在相同获准运行时、环境与任务下比较集成适配和直接使用。隔离环境证明与获准真实证明保持独立；支持状态只由对应兼容性证据提升。

先冻结契约，再以独立写入职责实现各切片，接入既有宿主，最后依据测得资格启用自动化。旧 Conversation 迁移不编造目标、不改作者、不自动执行。回退可停止新理解，同时保留目标状态、审计与明确恢复。计划、原始评估与执行报告仍在仓库忽略目录中；设计本身不改变发布状态。

当前源码行为（与上方目标设计区分）：宿主在 `continuity_schema` 持久化一份采用策略，并通过 `conversation.get` 投影。阶段跟随既有资格事实。禁用只阻止新的自动理解/派发。用户明确要求的执行保留原契约。枚举标签与调用方自造的 TrustedConfig / InteractionUseCase 事实不是已存储授权。生产 live 签发必须解析仓库中当前有效的 owner、准入评价会话，并由宿主生产器调用已绑定的获准 PersistentTurn、对已知用例的类型化输出评分后再评价。未绑定运行时保持不可用。hermetic observer 仅用于测试。重载重新校验该授权与收集回执，已撤销或已归档的 owner 不能再作为 live。归档或 owner 失效会在同一进程内拒绝下一次自动准入。`expanded` 要求不同的合格职责。TestEvidence 不能把真实模型资格提升为 Qualified。即使采用默认开启，offline 与 admitted-shadow 也不会自动派发。真实模型资格在另外授权并实际评估前保持 unknown。父卡片没有执行者徽章。这不是手机常驻。

## 13. 已冻结的机器契约（不是已上线能力）

闭合字段集位于 `schemas/client_bridge/conversation.json#continuousAssistant`。
Rust 与 Dart 投影由该嵌入字段生成。过渡端口返回带 `effectClass=none` 的
`unsupported_capability`。本节不声明已启用自动化、原生能力或发布证据。

本集合不包含任何回复形状契约。这里的类型都描述 LicoUp 校验并提交的宿主状态，没有一个描述 Agent 必须发送什么。Agent 的回复按它原本产出的样子显示。约束 Agent 自身回复文本的生成类型是缺陷。

| 公开生成类型 | 私有端口／叶模块 |
